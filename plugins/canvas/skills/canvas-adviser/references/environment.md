# Environment and installation

All commands below run from the resolved plugin root. The entrypoint explains how to find it.

1. Run `node scripts/doctor.mjs --json`. It uses only local prerequisite checks; `--probe` additionally checks the configured Canvas and ComfyUI HTTP endpoints. Missing optional ComfyUI/FFmpeg does not block Codex Plan text and image workflows.
2. Node must be 22.19+ on 22.x, or 24+. npm is needed to install the lockfile. If a suitable runtime is absent, inspect available runtimes/package managers and install only what the user's setup request covers. `load_workspace_dependencies`, when available in Codex, can locate a bundled runtime. Use its actual path without changing system aliases.
3. Run `node scripts/setup.mjs` for a fresh install or after a plugin version update. It runs `npm ci --include=dev --no-audit --no-fund` and builds the frontend from the sources in this plugin. This downloads npm packages into the plugin, including build tools even in a production environment; it does not install ComfyUI or models. If a managed installation is read-only, copy the plugin directory into a writable user-chosen working directory and run setup there.
4. `codex --version` and `codex login status` must work. `CANVAS_CODEX_PATH` can name the actual executable in a desktop app bundle. Discovery, generation, and doctor use that same executable. Without an override they prefer the installed CLI over the SDK’s npm dependency, so `npm start` cannot silently pin Canvas to the older bundled CLI. If sign-in is missing, the user must complete `codex login` interactively; never collect credentials in conversation. The installed CLI needs native image generation / `imagegen` for image nodes. Model availability may differ by account; preserve any requested supported model. Canvas discovers visible model IDs and variants using the installed CLI’s `app-server` `model/list`, including pagination. Never invent or hardcode a replacement list. Use each selected model’s reported default reasoning effort. If a model disappears, preserve its saved selection and explain that the user must select an available model.
5. Start with `npm start` in a persistent **normal terminal** session. When launching from a Codex task, use the execution tool's approved launch outside the task sandbox if the doctor reports restricted Codex runtime access. Canvas must be able to write the signed-in CLI's own state and initialize its local app server; a server started inside a restricted task inherits those restrictions, even when `codex login status` succeeds. Use the tool's normal permission mechanism, without adding self-elevation to the server or weakening the SDK agent's sandbox. Default URL is `http://127.0.0.1:8765`. Set `CANVAS_PORT` for a conflict and `CANVAS_DATA_DIR` for a stable location. By default data is in `$XDG_DATA_HOME/codex-canvas` or `~/.local/share/codex-canvas`. Do not use a plugin cache directory for persistent project data.
6. Verify `/health` reports `app: canvas` and `codexRuntime.ok: true`, run `node scripts/canvas.mjs providers/check --file <payload.json>` with `{"providerId":"codex-plan"}`, and open the URL. The doctor labels runtime access for its own process separately from that of the running server. Do not terminate an existing unrelated service to reclaim a port. Use Ctrl+C in the owning terminal to stop the Canvas process; stopping it cancels active work.

For a `readonly database` / `failed to initialize in-process app-server client: Operation not permitted` launch error, preserve unsaved browser edits and check for active jobs before restarting the owned Canvas server through the approved launch path above. Keep its existing `CANVAS_DATA_DIR`. Do not chmod the Codex database, copy credentials, replace `CODEX_HOME`, or disable the generated agent's sandbox to work around an inherited host restriction. Retry the failed node after the server access check passes.

`Settings → Connections` persists overrides at `<data-dir>/provider-settings.json`, with owner read/write permissions. This contains locally stored API keys if the optional API provider is configured. Never copy it into a project archive, plugin manifest, Git repository, or chat. Codex Plan has no key field. Its Fast (priority) checkbox exists only here, defaults off, and applies to supporting models in both workflow nodes and adviser chat. Never add Fast or effort controls to nodes or chat, and do not enable Fast without the user requesting it. The catalog is shared and cached in `codex-models.json`; a failed refresh shows the saved list with its status instead of a hardcoded fallback. Environment variables are documented in the plugin-root README; saved overrides take precedence.

`Settings → Storage` opens the current data folder in the host's file manager and changes its location. The change copies all Canvas data into a new or empty folder, activates it immediately, and retains the previous data as a backup. The browser flushes cached drafts first without committing them; saved workflows, drafts, and project ordering are retained. Active jobs, chats, or vd-runs block the change. The launch directory retains `.canvas-storage.json` pointing to the active location; keep this small locator or start directly with the new `CANVAS_DATA_DIR`. Use `/health`'s `dataDir` or the storage `info` RPC to find the current folder. Do not move a user's data merely to test the setting; use temporary test data for migration checks.

Detailed video inspection uses `ffprobe` from FFmpeg on the Canvas host. Without it, the viewer still displays browser-readable dimensions and duration and explains that FPS and embedded metadata are unavailable. The doctor reports `ffprobe` as optional; it is not needed to generate text or images.

For ComfyUI, check `/system_stats` and `/object_info` on the requested `COMFYUI_URL`. The bundled `custom_nodes/*.node.json` files describe required graph classes and exact loader filenames; inspect them to determine what is missing. The server's `custom_nodes/` contains Python extensions and is a different directory. Check installed model enums before changing a workflow. Base H3, H3 Turbo LoRA, Qwen image edits, and Z-Image have different dependencies. When available, the Drama plugin's `minimax-h3-comfyui` or `qwen-image-edit` guidance provides the installation details. A request to use Canvas alone does not authorize multi-gigabyte model downloads or restarting an existing ComfyUI server.

The Codex Plan connection check verifies local runtime access and lists supported choices without generating content. Actual text/image access is established by a user-requested generation. Explain the concrete returned error if CLI authentication, model entitlement, native image tools, or returned image capture fail.

For an older run reporting “completed without returning an image,” inspect the exact run's Codex trace before retrying generation. Native imagegen may already have saved a finished image in `<Codex home>/generated_images/<thread-id>/` without exposing image bytes in the SDK stream. The Canvas importer now checks that specific thread folder. Recover an existing generated image into the active Canvas assets store when available; preserve the original, and never substitute an image from another task or silently regenerate content just to recover a missed import.
